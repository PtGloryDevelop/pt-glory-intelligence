## ข้อเสนอแนวทาง

### หน้าแรก = สรุปคู่แข่งสัปดาห์นี้
แต่ละประเด็น: สิ่งที่เปลี่ยน → หลักฐานแอดคู่แข่ง → สินค้าเราที่ชนและผลงานแอดเรา → แนวทาง (ปรับโปร / ทำแอดใหม่ / ติดตาม) → เกณฑ์วัดผล (ไม่มีช่องผู้รับผิดชอบ — ดูส่วนยูนิต)
เรียงตาม ค่าแอดของสินค้าเราที่เกี่ยวข้อง × ขนาดการเปลี่ยนแปลง ด้านบนมีสรุป 3–5 ข้อสำหรับผู้บริหาร

### นิยาม "ใหม่"
| แบบ | ตรวจด้วย |
|---|---|
| แอดใหม่ (เห็นครั้งแรก) | โค้ด |
| ข้อเสนอ/ราคาเปลี่ยน | Jev ติดป้ายประเภทข้อเสนอ; โค้ดเทียบตัวเลข |
| มุมขายใหม่ | Jev |
| สินค้าใหม่ที่ชนกับสินค้าเรา | Jev |
| เร่งยิง (จำนวนแอด/เวอร์ชันเพิ่ม) / ไม่พบในรอบล่าสุด | โค้ด |

Ads Library ไทยไม่มีค่าแอดหรือยอดขายคู่แข่ง สัญญาณเร่งยิงเป็นแค่จำนวนแอด ไม่ใช่หลักฐานขายดี

### ช่วยหาคู่แข่ง
สินค้าเรา → คำค้นต่อสินค้า → ดึงแอดตามคำค้นรายสัปดาห์ → จัดอันดับเพจที่เจอบ่อย → Jev เสนอ คู่แข่งตรง/สินค้าทดแทน/ไม่เกี่ยว → ทีมยืนยัน → เข้ารายการติดตาม

### มูลค่า
วัดจากฝั่งเราเท่านั้น: การกระทำ → แผนทดลอง → เทียบต้นทุนต่อบทสนทนาและ ROAS ก่อน/หลัง 7–14 วัน → รายงานรายเดือนว่าทำตามข้อเสนอกี่เรื่อง ได้ผลกี่เรื่อง

### Jev
- เหมาะ: Choice/Noul/Score กับข้อความ — จัดกลุ่มสินค้า, ความสัมพันธ์คู่แข่ง, ประเภทข้อเสนอ, มุมขาย, ข้อความเปลี่ยนเชิงธุรกิจไหม
- ไม่เหมาะ: เขียนข้อความ, คำนวณ, วันที่, รูป/วิดีโอ (ต้อง OCR ก่อน)
- ภาษาไทยไม่ได้รับรองในเอกสาร → ทดสอบกับแอดจริง 50–100 ตัวที่ทีมติดป้ายก่อนใช้
- ราคา $0.042 / 1M input token (output ฟรี) — $10 ≈ 238M token เพียงพอสำหรับช่วงแรก
- ผลทุกอันเป็น "บทวิเคราะห์ AI"; มั่นใจสูง = AI เสนอให้ทีมยืนยัน, มั่นใจต่ำ = คิวรอทีมตรวจ; เกณฑ์มาจากผลทดสอบ

### ผู้ให้บริการ AI: Jev ก่อน อาจเปลี่ยนเป็น OpenAI
ผู้ใช้ตัดสินใช้ Jev เบื้องต้น และอาจเปลี่ยนไป OpenAI ภายหลัง จึงต้องออกแบบให้เปลี่ยนได้โดยไม่รื้อ:
- **คำถามและชุดคำตอบเป็นของเรา** — เช่น ป้ายประเภทข้อเสนอ, ความสัมพันธ์คู่แข่ง กำหนดในโค้ด/ข้อมูลของเว็บ ไม่ผูกกับรูปแบบของ Jev
- **ผลวิเคราะห์เก็บพร้อมที่มา** — ผู้ให้บริการ, รุ่นโมเดล, รุ่นคำถาม, ความมั่นใจ, เวลา; เปลี่ยนผู้ให้บริการแล้วผลเก่ายังแยกได้และเทียบกันได้
- **ผลที่ทีมยืนยันแล้วไม่ถูกเขียนทับ** เมื่อรันใหม่ด้วยโมเดลอื่น
- **ชุดทดสอบภาษาไทย 50–100 แอดที่ทีมติดป้าย (Q16) ใช้ซ้ำได้** — เป็นเกณฑ์ตัดสินว่าควรเปลี่ยนหรือไม่ โดยเทียบความแม่นและค่าใช้จ่ายบนชุดเดียวกัน
- ถ้าเปลี่ยนเป็น OpenAI จะได้ความสามารถที่ Jev ไม่มี: อ่านรูป (ข้อเสนอในภาพ เช่น "990.-"), ร่างไอเดียทดลอง/สรุปเป็นข้อความ — แต่ค่าใช้จ่ายต่อแอดสูงกว่ามาก และความมั่นใจไม่ได้มาเป็นความน่าจะเป็นแบบ Jev
- **ข้อเสนอ: ใช้คู่กันตามงาน ไม่ต้องเลือกอย่างเดียว**
  | งาน | ผู้ให้บริการ | เหตุผล |
  |---|---|---|
  | จัดกลุ่ม/ติดป้ายจำนวนมาก (กลุ่มสินค้า, ความสัมพันธ์คู่แข่ง, ประเภทข้อเสนอ, มุมขาย) | Jev | ถูกมาก, ให้ความน่าจะเป็นใช้ตั้งเกณฑ์ได้ |
  | อ่านข้อเสนอในรูป | OpenAI (vision) | Jev รับเฉพาะข้อความ; ทำเฉพาะแอดที่แคปชันไม่มีข้อเสนอ |
  | ร่างไอเดียทดลอง / สรุปเป็นข้อความ | OpenAI | Jev สร้างข้อความไม่ได้; ทำเฉพาะตอนผู้ใช้ขอ ไม่รันทั้งคลัง |
  งานแต่ละประเภทเลือกผู้ให้บริการแยกกันได้ และเปลี่ยนทีหลังได้ตามผลชุดทดสอบ

### ลำดับ
| ระยะ | งาน |
|---|---|
| A | รายการติดตาม + เก็บอัตโนมัติ + หน้า "อะไรใหม่สัปดาห์นี้" ด้วยโค้ดล้วน |
| B | ช่วยหาคู่แข่ง + ทดสอบ Jev ภาษาไทย |
| C | Jev ติดป้ายข้อเสนอ/มุมขาย/สินค้าที่ชน + จับคู่แอดเรา |
| D | ปุ่มลงมือ + วัดผล + รายงานมูลค่า |
| E | แจ้งเตือน + OCR |

งบ Apify: ระยะ A เก็บ 10–20 เพจ วันละครั้ง 2 สัปดาห์ แล้วคำนวณงบรายเดือนจากค่าจริง

### ข้อเสนอ 3 ชั้น
| ชั้น | กุญแจ | ความแม่น |
|---|---|---|
| แอด | `ad_id` | ข้อเท็จจริง |

| ชิ้นงาน (ข้ามเพจ/บัญชี) | ข้อความ normalize + perceptual hash รูปย่อ + ชื่อแอด | คาดเดา: ตรง 2/3 รวมอัตโนมัติ, ตรง 1/3 = "อาจซ้ำ" |

- ตัวเลขกลุ่ม: รวมผลรวมก่อนแล้วจึงหาร ห้ามเฉลี่ยอัตราส่วน; แตกผลรายเพจภายในชิ้นงาน
- แอดปิดแล้ว: ไม่ลบ; ค่าเริ่มต้นแสดง "มีค่าแอดในช่วงที่เลือก"; ตัวกรอง กำลังยิง / หยุดแล้วแต่มีผลในช่วง / เก็บถาวร / เปิดใหม่ยังไม่มีผล; ชิ้นงานยิงอยู่ถ้ามีแอดในกลุ่มยิงอยู่

- **กลุ่มสินค้า**: ใช้ "ยูนิต" แทน (ดูส่วนยูนิต)

## ฟังก์ชันที่ยืมจาก DeepSearch (deepsearch.thaiinsights.com)

DeepSearch เป็น social listening (โพสต์ปกติ + คอมเมนต์ Facebook/TikTok) ไม่ใช่ข้อมูลโฆษณา จึงยืมรูปแบบการนำเสนอ การคุมค่าใช้จ่าย และการแจ้งเตือน

### ผู้ใช้เลือกเอา
1. **บอกค่าใช้จ่ายก่อนกดดึง** — ทุกปุ่มเก็บแอดผ่าน Apify แสดงค่าประมาณ (ต่ำสุด–เพดาน) ก่อนกด, หยุดกลางคันได้ จ่ายเฉพาะที่ดึงแล้ว, ยอดสูงผิดปกติต้องยืนยันซ้ำ, มีหน้ารวมว่าใช้ไปเท่าไรกับอะไร → แทนการตั้งงบล่วงหน้า (ผู้บริหารข้อ 6)
2. **ดึงทีละขั้น จ่ายทีละขั้น** — 1) แอดใหม่ของเพจที่ติดตาม (ถูก) 2) ตรวจสถานะแอดเดิม (กลาง) 3) เก็บสื่อถาวร + Jev วิเคราะห์ (แพง)
3. **ขั้น 1 อัตโนมัติพร้อมเพดาน ขั้น 2–3 กดเอง** — ขั้น 1 สัปดาห์ละ 1–2 ครั้ง เฉพาะเพจที่ติดตาม หยุดเมื่อถึงเพดาน; พอให้หน้า "อะไรใหม่สัปดาห์นี้" มีข้อมูลทุกสัปดาห์ (Q5 ปิด)
4. **ค้นข้อมูลที่เก็บแล้วฟรี** — ค้น/กรอง/เทียบ อ่านจากฐานข้อมูลเรา ไม่ดึง Apify ใหม่ และบอกผู้ใช้ว่าการค้นไม่มีค่าใช้จ่าย
5. **แจ้งเตือนตามกฎ %** — เทียบ 7 วันล่าสุดกับ 7 วันก่อน เช่น แอดใหม่ของคู่แข่งเพิ่มเกิน X% (โค้ดล้วน) → ตอบ Q14 บางส่วน
6. **ปุ่มแคปซูลเลือกเพจแบบเดียวกันทุกหน้า** — ปุ่มแรก "ทั้งหมด"; ใช้ในหน้าแอด หน้าเทียบ และหน้าสรุป
7. **AI ช่วยตั้งค่า** — กรอกสินค้าเรา ระบบเสนอคำค้นและเพจคู่แข่ง (ขั้นช่วยหาคู่แข่ง)
8. **ส่วนแบ่งการยิงแอด + วิเคราะห์ว่าห่างกันตรงไหน** — จำนวนแอดที่ยิงอยู่ต่อคู่แข่งในกลุ่มสินค้า (กำกับว่าไม่ใช่ค่าแอด); ต่อยอด `/compare` ว่าต่างที่จำนวนแอด สัดส่วนรูป/วิดีโอ ประเภทข้อเสนอ หรือมุมขาย
9. **ส่งออก PDF** สำหรับที่ประชุม

### ผู้ใช้ไม่เอา
- สรุปรายสัปดาห์ทางอีเมล/LINE — ดูสรุปในเว็บ
- ถอดเสียงคลิป — ⚠️ Jev วิเคราะห์แอดวิดีโอได้เฉพาะข้อความแคปชันที่แหล่งให้มา ข้อเสนอที่พูดในคลิปจะไม่ถูกนับ ควรแสดงว่าผลวิเคราะห์ของแอดวิดีโอมาจากแคปชันเท่านั้น

### ไม่ทำ
- อ่านคอมเมนต์ใต้แอดคู่แข่ง — มีค่าแต่ Ads Library ไม่ให้คอมเมนต์ ต้องดึงแยก ต้นทุนและความเสี่ยงสูง เก็บไว้หลังระยะ D
- ตรวจยอดปลอม, ผู้ชมทับซ้อน, แฟนตัวยง, ระบบเครดิต — ไม่เกี่ยวกับการตัดสินใจเรื่องแอด
- โพสต์ปกติและคอมเมนต์คู่แข่ง: ใช้ DeepSearch คู่กัน (Starter ฟรี / Pro ฿599/เดือน) ไม่สร้างเอง

### ลำดับที่แนะนำ
1. บอกค่าใช้จ่ายก่อนกด + หน้ารวมค่าใช้จ่าย (ระยะ A)
2. ขั้น 1 อัตโนมัติพร้อมเพดาน ขั้น 2–3 กดเอง (ระยะ A)
3. ปุ่มแคปซูลเลือกเพจ (ระยะ A ไปพร้อมหน้าใหม่)
4. แจ้งเตือนตามกฎ % (ระยะ A–B)
5. AI ช่วยหาคู่แข่ง (ระยะ B)
6. ส่วนแบ่งการยิงแอด + วิเคราะห์ช่องว่าง (ระยะ C)

## Flow เทียบแอด `/compare/ads` (ตรวจ 2026-10-02 หลังออกแบบใหม่)

ขั้นตอน: เลือกแอดเรา → เลือกแอดคู่แข่ง → สรุปและวางแผน; เลือกแล้วเลื่อนขั้นอัตโนมัติ — 2 คลิกถึงหน้าเทียบ (จำนวนคลิกไม่ใช่ปัญหา)

### ปัญหา flow
1. ขั้นเลือกคู่แข่งแสดงทั้งหมด 892 แอด ไม่เกี่ยวกับสินค้าที่เลือก (เลือก Multi Green Veggie แต่ขึ้นสกินแคร์/แอสตาแซนธินก่อน) และยอมให้เทียบคู่ที่ไม่เกี่ยวกัน
2. ตัวกรองแอดเราเป็นบัญชีโฆษณา 72 บัญชี แทนที่จะเป็นยูนิต (~25)
3. "ข้อเสนอ" ต้องพิมพ์เองทั้งสองฝั่ง ทั้งที่ข้อความแอดมีอยู่ (เช่น "5 กระปุก + ชาแม่แย้ม แถมกระบอกน้ำ ส่งฟรี")
4. แผนทดลองเก็บใน localStorage + ดาวน์โหลดไฟล์ — ทีมไม่เห็น ระบบไม่รู้ว่าทำแล้วหรือได้ผล → ปิดวงวัดมูลค่าไม่ได้
5. เริ่มจากแอดเราเท่านั้น ไม่มีทางเข้าจาก "คู่แข่งทำอะไรใหม่"

### ข้อมูลที่ยังขาด
- **แอดเรา** (มีแค่ยอดรวม 30 วัน): เทียบค่ากลางยูนิตเดียวกัน, แนวโน้ม 4 สัปดาห์, อายุแอด, ชิ้นงานเดียวกันยิงกี่เพจ
- **คู่แข่ง** (มีแค่รูป ข้อความ สถานะ แพลตฟอร์ม; CTA "—"): วันเริ่มยิง/ยิงมากี่วัน (มีข้อมูลแล้ว แสดงในหน้าเพจ), จำนวนเวอร์ชัน (collation), แอดอื่นของเพจเดียวกัน 3–4 ตัว, ลิงก์ปลายทาง
- **ส่วนเทียบ**: ตารางเทียบทีละหัวข้อ — ข้อเสนอ / ราคา / มุมขาย / รูปแบบ / CTA / ยิงมากี่วัน — ไฮไลต์ช่องที่ต่าง
- เทียบได้ทีละคู่เท่านั้น — ควรเทียบแอดเรา 1 ตัวกับคู่แข่ง 3–5 ตัวในสินค้าเดียวกัน

### ลำดับที่แนะนำ
1. เลือกแอดเราแล้วแสดงแอดคู่แข่งที่เกี่ยวข้องก่อน (ช่วงแรกใช้คำค้นของยูนิต ต่อไปใช้ Jev) + ตัวกรองเป็นยูนิต
2. แสดงข้อมูลที่มีอยู่แล้ว: ยิงมากี่วัน, จำนวนเวอร์ชัน, ค่ากลางยูนิต, ลิงก์ปลายทาง
3. ตารางเทียบทีละหัวข้อ + ระบบกรอกข้อเสนอให้ก่อน (โค้ดดึงราคา/คำ "แถม" "ส่งฟรี" → ต่อไป Jev) ทีมแก้เฉพาะที่ผิด
4. บันทึกแผนทดลองลงฐานข้อมูล แสดงในเมนู "แผนทดลอง" แทนดาวน์โหลดไฟล์
5. ทางเข้าจากแอดคู่แข่ง ("เทียบกับแอดเรา" → เสนอแอดเราในยูนิตที่ชน) + เทียบหลายตัว

ข้อ 1–2 ไม่ต้องใช้ AI

## ข้อเสนอเพิ่มเติม

1. **ทดสอบสรุปด้วยมือก่อนสร้าง (1–2 สัปดาห์)** — ทำสรุป 3–5 ข้อจากข้อมูลคู่แข่งที่มี (892 แอด) เป็นเอกสารหน้าเดียว ส่งผู้บริหาร ถามว่าข้อไหนมีประโยชน์ → รู้ว่าควรสร้างอะไรก่อนลงแรงกับหน้า "อะไรใหม่สัปดาห์นี้"
2. **ขอคำค้นจากหัวหน้าแต่ละยูนิต 3–5 คำ** (เช่น U15: ผงผัก ดีท็อกซ์ ไขมันในเลือด) — ไม่ต้องเขียนโค้ด; ใช้เก็บแอด, จับคู่คู่แข่งกับยูนิต และช่วยตอบ "คู่แข่งคือใคร"
3. **⚠️ ตรวจคำโฆษณาเกินจริงในแอดเรา** — พบข้อความแอด "RE โปร 9.9" อ้างผลรักษา ("ความดันกระเจิง… ฟื้นฟูหลอดเลือดถาวร… หมอเบายาแล้ว") และชื่อบัญชีมีคำ "ลดเบาหวาน", "สลายนิ่ว"; ผลิตภัณฑ์เสริมอาหารอ้างรักษาโรคเสี่ยงกฎหมายโฆษณา (อย.) และนโยบาย Meta (แอดถูกปฏิเสธ/บัญชีถูกจำกัด) — Jev Noul "ข้อความนี้อ้างผลรักษาโรคหรือไม่" ติดป้ายให้ทีมตรวจ; ระบบคัดกรองเท่านั้น ไม่ใช่ความเห็นทางกฎหมาย; มีค่าต่อผู้บริหารโดยตรง (ลดความเสี่ยงบัญชีถูกแบน)
4. **ประวัติคู่แข่งมีเท่าที่เราเก็บเอง** — Ads Library ไม่เก็บประวัติให้; เก็บห่างจะพลาดแอดที่เปิดแล้วปิดเร็ว → เริ่มเก็บขั้น 1 อัตโนมัติให้เร็วที่สุดแม้หน้าเว็บยังไม่เสร็จ เพราะประวัติย้อนหลังสร้างทีหลังไม่ได้ (ตอนนี้ `/collect` ยังปิด ต้องให้ admin เปิด)
5. **ตัวชี้วัดว่าเว็บคุ้มไหม** — ผู้บริหารยังเปิด Ads Library เองไหม (ถามเดือนละครั้ง), จำนวนแผนทดลองต่อเดือนและที่ได้ผล, ค่า Apify + AI ต่อเดือนเทียบผล — หน้าสรุปตัวเลข 3 ตัวพอ

ข้อ 1–2 ทำได้ทันทีโดยไม่รอ Codex; ข้อ 3 น่าจะเป็นฟีเจอร์ที่ผู้บริหารเห็นค่าเร็วที่สุด
