## 1. เป้าหมายของระบบ

สร้างเครื่องมือภายในสำหรับผู้บริหาร ทีมการตลาด และหัวหน้าทีมแอด ให้เข้ามาดูผลแอดบริษัท ส่องแอดคู่แข่ง เปรียบเทียบหลักฐาน และวางแผนทดลองได้ในเว็บเดียว

คำถามที่ระบบต้องช่วยตอบ:

1. ผลแอดเราช่วงนี้เปลี่ยนไปอย่างไร และแอดไหนควรเปิดตรวจ?
2. คู่แข่งมีแอด ข้อเสนอ หรือข้อความอะไรที่เพิ่งพบ?
3. เมื่อสินค้า/ปัญหาลูกค้าใกล้กัน เราควรทดลองเปลี่ยนคำเปิด ข้อเสนอ หรือครีเอทีฟอย่างไร?
4. จะกลับมาตรวจผลทดลองด้วยข้อมูลฝั่งเราอย่างไร?

ผู้ใช้ระบุหลายครั้งว่าไม่ต้องการหน้าแรกที่เป็นกริดภาพอย่างเดียว จึงเปลี่ยนทิศทางเป็นภาพรวมที่มีตัวเลข ตาราง และทางเข้าตรวจหลักฐานก่อนตัดสินใจ คลังสื่อยังเป็นส่วนค้นหลักฐาน ไม่ใช่จุดจบของ Flow

ระบบนี้เป็นเครื่องมือบริษัท ไม่มีแพ็กเกจสมาชิก ระบบเครดิตของผู้ใช้ หรือหน้าขายบริการ

- ส่งออก CSV เฉพาะแถวที่แสดง พร้อมวันที่/สกุลเงินและป้องกันข้อความกลายเป็นสูตรใน spreadsheet
- ด้านล่างมีข้อความ/ข้อเสนอคู่แข่ง เพจที่เพิ่งพบแอดเพิ่ม รายการติดตาม และทางไปเขียนแผน
- กราฟในแถวอ่านค่าแอดรายวันจริง ส่วนแท่งใต้ KPI เปรียบเทียบยอดรวมสองช่วง ไม่ใช่เส้นแนวโน้มรายวันที่สร้างขึ้น
- ข้อมูลบางส่วนเปิดไม่ได้ยังแสดงส่วนอื่นและทางลองใหม่
- ลิงก์ภาพย่อคู่แข่งบางรายการหมดอายุ จึงมีทางเปิดข้อมูลหลักฐานแทนภาพที่โหลดไม่ได้

### 6.3 เปรียบเทียบแอดและแผนทดลอง

- เก็บหลักฐานภาพ/วิดีโอ ข้อความ ชื่อเพจ ตัวตนแอด ชุดข้อมูล และช่วงผลลัพธ์
- ฝั่งเรามีผลลัพธ์จริง; ฝั่งคู่แข่งไม่ใส่ค่าแอด ยอดขาย หรือ ROAS ที่ไม่มีแหล่งข้อมูล
- เลือกแอดจากคลังและส่งต่อเข้าเทียบได้ เปลี่ยนคู่แอด/รีโหลด/กลับหน้าต้นทางโดยรักษาช่วงวันที่
- กรอกสินค้า/ปัญหาลูกค้าที่เทียบ ข้อเสนอแต่ละฝั่ง สิ่งที่จะเปลี่ยน เหตุผล และวิธีวัดผล
- ดาวน์โหลด brief เป็น Markdown พร้อมหลักฐานและข้อมูลอ้างอิง
- ร่างปัจจุบันเก็บในเบราว์เซอร์ของผู้ใช้ตามคู่แอด ไม่ใช่ฐานข้อมูลแผนร่วมของทีม และไม่สั่งปรับแอดจริง

### 6.4 ภาพคมชัดและลดการโหลด

- แก้การใช้ภาพย่อ 64×64 โดยอ่านภาพ/thumbnail ขนาดใหญ่จาก endpoint ที่มีสิทธิ์
- ทดสอบภาพหน้าแรกของคลัง 24 แอดได้ภาพกว้าง 362–1080 px ในกรณีที่ตรวจ
- Resolve เฉพาะแอดที่แสดง และอัปเดตเป็นชุดละ 4 ใบ; ใช้แคชใน process เพื่อลดการเรียกซ้ำ
- ใช้ `AdImage`, `sizes`, `srcset`, WebP quality 85 และ lazy loading ตามพื้นที่แสดง
- รายละเอียดภาพนิ่งยังใช้ต้นฉบับ; URL ส่วนตัวที่มีลายเซ็นไม่ถูกส่งผ่าน public optimizer เพื่อยืดอายุสิทธิ์
- ตัวอย่างภาพจริง 3 ใบลด bytes รวมจาก 109,668 เป็น 72,646 (**33.8%**); เป็นผลเฉพาะตัวอย่าง ไม่ใช่ผลลดทุกภาพหรือผลวัด Core Web Vitals ของผู้ใช้ทั้งหมด
- หาก optimizer ล้มเหลวจะลองต้นฉบับก่อน; AVIF และการสร้างหลายขนาดให้ private archive ล่วงหน้ายังไม่ได้เพิ่ม
- แคช resolve ภาพยังอยู่ในเครื่อง/process การเปิดครั้งแรกและการเริ่ม server ใหม่อาจต้องรอต้นทาง

### 6.5 ดูวิดีโอในเว็บ

- สื่อที่มีตัวตนวิดีโอจริงมีปุ่มดูวิดีโอ เปิดเมื่อผู้ใช้เลือกดู
- หาก Meta ให้ไฟล์ต้นทาง ใช้ player ที่มี controls; หากติดสิทธิ์ ใช้ official ad preview ที่ตรวจ URL แล้ว
- ทดสอบเล่น U11, VDO 140 และ VDO 36 จริงผ่าน preview รวมทั้งบาง Flow บนมือถือและหน้าเทียบ
- ไม่ autoplay หรือโหลดผู้เล่นทุกใบตอนเปิดกริด
- แก้ปุ่มท้าย modal ถูกตัด: แยก footer ออกจากเนื้อหาที่เลื่อน ตรวจจอคอม แนวตั้ง และแนวนอน
- การเล่นยังขึ้นกับ Meta/สิทธิ์/สภาพแอด ไม่รับประกันว่าทุกวิดีโอทุกบัญชีจะเล่นได้

### 6.6 ความเร็วและความปลอดภัย

- ปรับ query ค้นหา/นับแอด/อ่านประวัติรายวันด้วย migration ปลายทาง 0049–0053
- ผลวัดเฉพาะ query: ช่วงกว้างตามค่าแอดประมาณ 3.6 → 1.2 วินาที; ค้นเครื่องหมายในคลังประมาณ 11.9 → 1.9 วินาที ไม่ใช่ SLA หรือเวลารวมโหลดหน้า
- ใช้ caller JWT/RLS และตรวจบทบาทก่อนอ่านข้อมูลการเงิน; RPC ที่ใช้สิทธิ์เฉพาะต้องตรวจผู้เรียกและ snapshot
- Token และคีย์ต้นทางอยู่ฝั่ง server ไม่ส่งเข้า JavaScript ของเบราว์เซอร์หรือเอกสารนี้
- ตรวจ host/URL ภาพและ iframe; ไม่ render HTML ที่ผู้ให้บริการส่งมาโดยตรง
- เปิดภาพรวม ค้นหา และเทียบไม่ได้สั่งเก็บ Apify หรือนำเข้าข้อมูลเพิ่มเอง

## 8. หลักการคำนวณและการอ่านข้อมูล

| ตัวชี้วัด | สูตร / เงื่อนไข |
| --- | --- |
| ROAS (Meta) | มูลค่าซื้อที่รายงานรวม ÷ ค่าแอดรวม |
| ค่าทัก | ค่าแอดรวม ÷ บทสนทนารวม |
| Hook rate | ยอดดูวิดีโอที่ต้นทางรายงานในฟิลด์ที่ใช้ ÷ Impressions × 100 |
| % ปิดจริง | ยอดปิดจากระบบขาย ÷ จำนวนทัก × 100; ยังไม่มีแหล่งนี้ |
| % เปลี่ยนช่วง | (ค่าช่วงนี้ − ค่าช่วงก่อน) ÷ ค่าช่วงก่อน × 100 |
| แอดคู่แข่งเพิ่งพบ | วันที่ระบบเห็นครั้งแรกในข้อมูล ไม่ใช่ข้อสรุปวันเปิดแอด |

ข้อกำหนด:

- รวมตัวเศษและตัวหารในขอบเขตเดียวกันก่อนหาร ไม่เฉลี่ย ROAS/ค่าทักรายแอด
- แยกสกุลเงิน ไม่บวก THB กับสกุลเงินอื่น
- ไม่คำนวณอัตราส่วนเมื่อข้อมูลที่จำเป็นขาดหรือฐานหารไม่เหมาะสม
- เทียบ % เฉพาะช่วงยาวเท่ากัน อยู่ในขอบเขตนำเข้า ข้อมูลฟิลด์ที่ใช้ครบ และฐานเดิมเป็นบวก
- วันที่ไม่มีรายการไม่เติมเป็นศูนย์; coverage ของแถวที่บันทึกครบไม่ได้พิสูจน์ว่าต้นทางรายงานทุกแอดทุกวัน
- กราฟค่าแอดรายวันเว้นช่องเมื่อไม่ทราบค่า ส่วน % รายแอดต้องมีค่าครบทุกวันทั้งสองช่วง
- แอดมีค่าแอดในช่วงที่เลือกอาจหยุดแล้วในปัจจุบัน ป้ายสถานะล่าสุดไม่ใช่สถานะย้อนหลังทุกวัน
- ตัวเลขสูง/ต่ำหรืออันดับไม่ได้เป็นคำสั่งเพิ่มงบ/พักแอดโดยอัตโนมัติ
- เพจไม่ใช่แบรนด์; การรวมหลายเพจเป็นแบรนด์ต้องมี mapping ที่ตรวจได้

## 9. งานที่ยังไม่เสร็จและลำดับที่แนะนำ

### ลำดับ 1: สิทธิ์และความสดของข้อมูล

1. ตรวจและมอบสิทธิ์ตัวเพจที่เหลือให้ system user ตามขอบเขตที่บริษัทอนุญาต แล้วอัปเดตชื่อ
2. สรุปวิธีนำเข้าแอดบริษัทอัตโนมัติ ความถี่ และ host ที่จะใช้งานจริง; ปัจจุบันเป็น local bridge ที่สั่งนำเข้าได้
3. ยืนยันรายชื่อเพจคู่แข่ง คำค้นต่อ UNIT และเพดานค่าใช้จ่ายก่อนเปิดเก็บตามรอบ
4. วางการเก็บภาพคู่แข่งที่หมดอายุให้สอดคล้องกับสิทธิ์และต้นทุน; ไม่ถือว่าการแสดง fallback แก้ไฟล์ต้นทางแล้ว

### ลำดับ 2: ทำให้การเทียบช่วยตัดสินใจมากขึ้น

1. กำหนดคำค้นของแต่ละ UNIT เพื่อเสนอแอดคู่แข่งที่เกี่ยวข้องก่อน
2. เพิ่มมุมเทียบข้อเสนอ ราคา คำเปิด รูปแบบ CTA และหลักฐานหลายแอดต่อสินค้าเมื่อข้อมูลรองรับ
3. ทำกลุ่มสื่อจาก creative/video identity ให้ชัดก่อนเสนอชิ้นงานซ้ำข้ามเพจ/บัญชี
4. การจับซ้ำจากข้อความ/ภาพเป็นการคาดเดา ต้องให้ทีมตรวจ แยกกลุ่ม และรักษาหลักฐานรายแอดได้

### ลำดับ 3: แผนทดลองร่วมและการวัดผล

1. บันทึกแผนลงฐานข้อมูล พร้อมสิทธิ์ เวอร์ชัน และหลักฐาน แทนร่างในเบราว์เซอร์อย่างเดียว
2. กำหนดเกณฑ์เปรียบเทียบก่อน/หลัง 7–14 วัน แล้วรายงานผลจากตัวเลขฝั่งเรา
3. เชื่อมระบบขายเมื่อพร้อมเพื่อ % ปิดจริง; หากต้องจัดอันดับกำไรต้องมีต้นทุนสินค้า/รายได้จริงเพิ่มเติม
4. รายงานการประชุม/PDF และการแจ้งเตือนในเว็บเป็นงานต่อ ไม่ใช่ฟังก์ชันที่ยืนยันว่าเสร็จแล้ว

### ลำดับ 4: AI ที่อ้างหลักฐานได้

- บริบทธุรกิจเสนอ Jev สำหรับการติดป้ายข้อความ และอาจใช้ OpenAI สำหรับภาพ/สรุปตามงาน แต่ยังไม่เรียกใช้งานจริง
- ทดสอบภาษาไทยกับ 50–100 แอดที่ทีมติดป้ายก่อนใช้อัตโนมัติ
- แยกข้อเท็จจริงจากบทวิเคราะห์ เก็บหลักฐาน รุ่นโมเดล รุ่นคำถาม ความมั่นใจ และเวลาวิเคราะห์
- ผลที่ทีมยืนยันแล้วไม่ควรถูกเขียนทับเมื่อเปลี่ยนผู้ให้บริการ
- OCR/การอ่านข้อเสนอในภาพยังเป็นงานต่อ; ผู้ใช้ไม่ได้เลือกงานถอดเสียงคลิปในบริบทสัมภาษณ์
- เอกสารนี้ไม่ยืนยันราคา/คุณสมบัติปัจจุบันของผู้ให้บริการ AI ตามข้อความราคาเก่าในเอกสารแนวทาง

### ลำดับ 5: เตรียมเปิดใช้งานจริง

- เปลี่ยน/จัดการ local bridge ให้ทำงานบน host จริง พร้อมสิทธิ์ source export ที่ชัดเจน
- จัดการ secret, migration, scheduler, budget และ media cache ตามสภาพแวดล้อมจริง
- แก้ baseline tests ที่ค้าง และผ่าน release gate ก่อนอ้างว่าพร้อมขึ้นระบบจริง
- ทดสอบผู้ใช้ทีมจริงทั้งผู้บริหาร/การตลาดใน Flow ที่ใช้ตัดสินใจ
