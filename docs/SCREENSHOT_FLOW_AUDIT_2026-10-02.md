# ตรวจและแก้ Flow จากภาพทีม — 2 ตุลาคม 2569

ตรวจตามเส้นทาง หน้าแรก → แอดเรา → คู่แข่ง → รายละเอียด → เปรียบเทียบ และปรับหน้าแรกตามภาพเขียน Flow ล่าสุดของทีม โทนสว่างเรียบคมและเน้นภาพแอดตามที่เลือกไว้

## จุดที่แก้

1. **ภาพแอดถูกตัดแม้ใช้ contain:** กริดในกรอบภาพปล่อยให้แถวขยายตามรูป แต่กรอบซ่อนส่วนเกิน แก้ใน Creative ที่ใช้ร่วมกันให้แถวและภาพอยู่ในขนาดกรอบ ทั้งคลัง รายละเอียด และหน้าเทียบ
2. **เทียบแล้วต้องเลื่อนอ่านยาว:** จำกัดพื้นที่ข้อความให้อ่านและเลื่อนด้วยคีย์บอร์ดได้โดยเก็บข้อความครบ ย้ายสินค้าหรือความต้องการที่ทีมจะเทียบไว้ก่อนคู่แอด
3. **กลับคลังแล้วคำค้นหรือหน้าเปลี่ยน:** ใช้ query จาก router และรักษา returnTo รวมตัวกรองกับข้อมูลคู่แข่งที่เลือกไว้แน่นอน
4. **เลือกแอดใหม่ในหน้าเทียบแล้ววันที่กลายเป็น 30 วัน:** ใช้ API รายวันร่วมกันทั้งตอนเปิด เลือกใหม่ และกู้รายการเมื่อมาจากหน้าแรกหรือ Command Center
5. **หน้าเกินจำนวนจริงกลายเป็นรายการว่าง:** ปรับไปหน้าสุดท้ายและแก้ URL ให้ตรงกัน
6. **วิดีโอไม่มี ID ใน metadata:** ค้น ID เพิ่มเฉพาะคำขอเล่นวิดีโอ คืนภาพสำรองเมื่อสิทธิ์ต้นทางไม่ให้ไฟล์ เปิดวิดีโอด้วย controls และ preload=none
7. **หน้าแรกไม่ตรงงานทีม:** เปิดด้วย KPI และคลังของเรา เลือกวันที่/ยูนิต/เพจได้จริง เพิ่ม Command Center ส่วนภาพรวมคู่แข่งอยู่ในเครื่องมือวิเคราะห์
8. **เปลี่ยนคู่แอดแล้วรีโหลดกลับไปคู่เดิม:** บันทึกคู่ที่เลือกลง URL ร่วมกับรายการในเบราว์เซอร์ ทดสอบเลือกแอดเราคนละตัว รีโหลด กู้รายการ และกลับคลัง โดยช่วงวันที่ ค่าแอด และตัวกรองยังตรงกัน

## ตรวจข้อมูล

นำเข้าจริงครบ 72 บัญชี / 73,360 แอด พร้อมข้อมูลรายวัน ตรวจช่วง 7 วันจากฐานข้อมูลปลายทาง 3,812 แอด / 18,336 แถวรายวัน: ยอดรวมจากตารางตรงกับ RPC และสรุปครบทุกหน้า สูตรถ่วงน้ำหนักตรงกัน การตรวจเป็น transaction อ่านอย่างเดียวและ rollback

Viewer และผู้ไม่เข้าสู่ระบบเข้าถึง RPC การเงินไม่ได้ ช่วงที่ทดสอบไม่มีค่าขาด จึงไม่ได้อ้างว่าทดสอบ null-path ด้วยข้อมูลจริง

## สถานะตรวจหน้าจอ

Production build ผ่าน การทดสอบ Flow รายวันด้วยข้อมูลจริงผ่านแล้วเมื่อ 2 ต.ค. 2569 และตรวจภาพที่บันทึกไว้รอบสุดท้ายเมื่อ 3 ต.ค. 2569

- `scripts/check-owned-performance.mjs`: ช่วงวันที่ทั้ง 9 แบบ โดยอ่านพร้อมกันครั้งละ 3 ช่วง การค้นแคปชันจริง ยูนิต/เพจ/สถานะ การจัดอันดับทั้ง 7 แบบ หน้าถัดไป/ก่อนหน้า วันที่กำหนดเอง รีโหลด รายละเอียดด้วยคีย์บอร์ด เปลี่ยนแอดในหน้าเทียบ กู้รายการ และกลับตัวกรองเดิมผ่าน ไม่ใช้ข้อมูลจำลองในชุดนี้
- `scripts/check-owned-daily.mjs`: ยอดรวมและสูตรถ่วงน้ำหนักแยกสกุลเงินครบทุกหน้า ช่วงข้อมูล วันเริ่มที่นำเข้า การเรียงวันเริ่ม และสิทธิ์การเงินผ่าน การตรวจฐานข้อมูลอ่านอย่างเดียวและ rollback
- เส้นทางเดิมผ่าน `check-screenshot-flow.mjs`, `check-business-comparison.mjs`, `check-owned-return.mjs`, `check-catalog-return.mjs` และ `check-dashboard-flow.mjs` ก่อนปิดงาน ส่วนการทดสอบกรณี null/ระบบต้นทางขัดข้อง/หน้า URL ไม่ถูกต้องบางกรณีใช้ response ที่ดักในเบราว์เซอร์ ไม่ใช่กรณีที่เกิดในข้อมูลรายวันจริง
- การตรวจ imports, TypeScript/build, ESLint ของไฟล์ที่เกี่ยวข้อง และชุดตรวจ security/parser/selection/navigation/video fallback ผ่านตามขอบเขตที่ตรวจ

ภาพจริงอยู่ใน `test-artifacts/owned-performance/`: `home-desktop.png`, `library-desktop-viewport.png`, `creative-card.png`, `detail.png`, `rankings-desktop.png`, `library-mobile.png`, `home-creative-mobile.png` และ `rankings-mobile.png` ตรวจเดสก์ท็อป 1440×1000 และมือถือ 390×844 ภาพเต็ม ตัวเลข KPI ปุ่ม ตัวกรอง และรายละเอียดอ่านได้ ไม่มี horizontal overflow ในการทดสอบ ป้ายชื่อที่ยังเป็นรหัสจากต้นทางเก็บตามข้อมูลจริง

เมื่อ 3 ต.ค. เปิดเซิร์ฟเวอร์ localhost ใหม่และตรวจเข้าหน้าคลังด้วยบัญชีทดสอบ อ่าน API ช่วงทั้งหมดและวันนี้ตามปฏิทินกรุงเทพฯ ผ่าน วันที่ยังไม่มีข้อมูลไม่ย้อนเลือกวันก่อนหน้า เก็บภาพมือถือเพิ่ม `rankings-mobile-viewport.png` และ `ranking-card-mobile.png` แล้วตรวจความคมของข้อความกับภาพจริง ไม่มีการนำเข้าหรือเก็บแอดเพิ่มในรอบนี้

## แก้คำขอข้อมูลที่หมดเวลา

พบการเลือกแผน query ที่ไม่เหมาะกับช่วงกว้าง การนับแอดซ้ำจากทุกแถวรายวัน และการอ่านแคปชันจาก JSON ทุกแถว แก้ด้วย migration 0049–0053: อ่านวันเริ่มเฉพาะรายการที่ต้องแสดง ใช้แผน query ตามตัวกรอง นับจากกลุ่มแอดที่คำนวณแล้ว และขยายช่องค้นหา generated ที่มีอยู่ให้รวมชื่อกับแคปชัน ใช้ดัชนีเดิมเมื่อคำค้นมีอักขระพอ ส่วนคำสั้นหรือเครื่องหมายใช้ข้อความที่เก็บไว้โดยตรง คำค้น literal `%`, `_` และ backslash ยังมีความหมายเดิม

ตรวจผล JSON ก่อนและหลังให้ตรงกันทั้งสรุปและรายการ รวม 13 กรณีค้นหา/ตัวกรองของ RPC รายวัน และ 6 กรณีของ RPC คลังเดิมทั้งสอง overload การวัดบนฐานข้อมูลปลายทางพบช่วงกว้างตามค่าแอดลดจากประมาณ 3.6 เหลือ 1.2 วินาที และคำค้นเครื่องหมายในคลังเดิมลดจากประมาณ 11.9 เหลือ 1.9 วินาที ตัวเลขนี้เป็นผลวัด query เฉพาะรอบ ไม่ใช่ SLA หรือเวลารวมการโหลดภาพ ผ่านการอ่านช่วงวันที่พร้อมกันหลังแก้โดยไม่เพิ่ม timeout ของ API หรือสิทธิ์ผู้ใช้

ใช้ความสามารถเดิมของ PostgreSQL ตาม [ALTER TABLE](https://www.postgresql.org/docs/17/sql-altertable.html) และ [pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html) มี migration ย้อนกลับและตรวจสิทธิ์ของฟังก์ชันหลังนำขึ้นฐานข้อมูลปลายทาง

## ข้อจำกัด

%ปิดข้ามการเชื่อมระบบขายตามคำตอบผู้ใช้ AI ยังไม่เปิดใช้งาน ไม่มีข้อมูลผลลัพธ์การเงินคู่แข่ง การตรวจนี้ไม่เริ่มงานเก็บ Apify ไม่เปลี่ยนฐานข้อมูลเว็บเดิมและไม่สั่งเปลี่ยนแอดจริง

วิดีโอแอดเราอาจคืนภาพสำรองเมื่อสิทธิ์ Meta ไม่ให้ไฟล์ ยังไม่ยืนยันการเล่นวิดีโอแอดเราจากต้นทางจริงครบทุกบัญชี ผลที่ผ่านครอบคลุม fallback และการควบคุมวิดีโอคู่แข่งตามกรณีที่ตรวจ ภาพชุดนี้ใช้ข้อมูลที่นำเข้าถึง 2 ต.ค. 2569 วันที่ใหม่กว่านั้นต้องนำเข้าข้อมูลเพิ่ม ไม่เลื่อนวันที่ที่ผู้ใช้เลือกหรือเติมยอดเป็นศูนย์

เว็บเปิดทดสอบบน localhost ยังไม่ได้ deploy เว็บรุ่นนี้ขึ้นระบบจริง

ชุดทดสอบ release ทั้งโครงการมีข้อผิดพลาด baseline ที่บันทึกไว้ก่อนหน้านี้ จึงไม่อ้างว่าผ่าน release gate ทั้งหมด รายงานนี้ยืนยันเฉพาะเส้นทางและข้อมูลที่ตรวจจริง
