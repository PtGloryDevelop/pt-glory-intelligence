### 3.2 `end_date` ขัดกับ Master Spec §4 — 100% ของข้อมูลจริง

```
active ads: 342 / 342
active ads ที่มี end_date ไม่เป็น null: 342 / 342
```

**ทุกแถวเป็น active และทุกแถวมี end_date** กฎ normalize ของ Master Spec (`if active → end_date = null`, เก็บ raw ไว้ที่ `network_end_date_raw`) ไม่ใช่กรณีขอบ — มันคือ **100% ของ dataset** ถ้าไม่ implement กฎนี้ ทุก "ad age" และทุก "active/inactive" จะผิดทั้งระบบ

### 3.3 `meta_page_id` ไม่มีอยู่จริง และ page id แตกต่างกัน 39%

- Data Contract ระบุ `page_id` และ `meta_page_id` แยกกัน — **ในข้อมูลจริงไม่มีฟิลด์ `meta_page_id` เลย** ทั้ง top-level และใน snapshot
- ตัวเลขใน `page_profile_uri` **ต่างจาก `page_id` ใน 132 / 342 แถว = 39%**

ตัวอย่าง: `page_id = 101994122048475` แต่ `page_profile_uri = https://www.facebook.com/100069521486473/`

**สรุป:** กฎ "Keep them separate" ของ Spec **ถูกต้องและจำเป็น** แต่ชื่อฟิลด์ในเอกสารไม่ตรงกับความจริง ต้องแก้ Data Contract เป็น `page_id` + `page_profile_numeric_id` (สกัดจาก URI) และตัด `meta_page_id` ออกจนกว่าจะพบ collector ที่ส่งมาจริง

### 3.4 collection metadata อยู่คนละชั้นกับที่ Data Contract เขียนไว้

Data Contract วาง `source`, `collector_version`, `collection_run_id`, `collected_at`, `query`, `country`, `active_status`, `media_type`, `stop_reason` ไว้ในระดับ **ad**

ในข้อมูลจริง metadata อยู่ที่ระดับ **run** (`run.report.json`) ไม่ได้อยู่ในแต่ละ ad:

```

partial_targets, incomplete_targets, ads_seen_total, unique_ads_total,
fatal_error, supabase, reports[]

reports[i]: target, started_at, finished_at, warmup_graphql_matches,
            pages_limit, completed_pages, stopped_reason, has_next_page,
            steps, raw_unique_ads, unique_ads, filtered_out_ads, relevance_mode
```

**ถูกต้องกว่าอยู่แล้ว** — metadata ควรอยู่ที่ `collection_runs` ไม่ควรทำซ้ำในทุกแถว ad ต้องแก้ Data Contract ให้ตรงความจริง

## 5. Production Architecture — Phase 0–1

### 5.1 Stack ที่เสนอ

| ชั้น | เลือก | เหตุผล |
|---|---|---|
| Frontend + API | **Next.js App Router (TypeScript)** | ทีมใช้อยู่แล้วในโปรดักต์พี่น้อง ลด learning cost, server action/route handler ปิด secret ได้ |
| Database | **Supabase Postgres** | ตาม `ARCHITECTURE.md` |
| Auth | **Supabase Auth** + allowlist โดเมนบริษัท | internal-only ตาม CLAUDE.md ข้อ 4 |
| Server secrets | env ฝั่ง server เท่านั้น | ห้าม `NEXT_PUBLIC_*` กับ service-role key |
| Background jobs | **ตาราง `background_jobs` + worker แยก process** | Phase 1 ยังไม่ต้องใช้ queue จริง |
| Testing | Node test runner (unit/integration) + **Playwright** (E2E) | ตาม `TEST_STRATEGY.md` |
| Media | **เก็บ URL + metadata เท่านั้น ไม่ mirror ไฟล์** | ตาม `ARCHITECTURE.md` §Media Strategy |

### 5.2 Data flow

```
Collector JSON (upload)
   ↓  validate schema (zod) — reject ทั้งไฟล์ถ้าโครงผิด
   ↓  normalize — ตัด 5 forbidden fields ทิ้งที่นี่
   ↓  preview (ยังไม่เขียน DB)
   ↓  [ผู้ใช้กดยืนยัน]
   ↓  transaction:
        upsert pages          → page_observations (append)
        upsert ads            → ad_observations  (append)
        insert dataset_ads    (membership)
        insert collection_run
        compute + insert dataset_quality
   ↓  Dataset พร้อมใช้
   ↓  Ads Explorer → Ad Detail Drawer
```

**หลักการที่ห้ามละเมิด:** master entity ถูก upsert (ไม่ทำซ้ำ), observation ถูก append (ไม่ทับของเดิม) — ตาม CLAUDE.md ข้อ 10 และ 11

### 5.3 ชั้นที่ต้องแยกกันเด็ดขาด

```
raw collector shape  →  normalizer  →  canonical domain type  →  UI
```

UI **ห้าม** import type ที่มีรูปร่างของ collector ตรงๆ (ตาม `ptg-architecture`: "avoid coupling the UI directly to raw collector shapes") — ถ้า collector เปลี่ยน schema ต้องกระทบแค่ normalizer

### 6.5 RLS concept

```
ทุกตารางเปิด RLS
role: viewer | analyst | admin   ← ⛔ ต้องให้เจ้าของยืนยันก่อน (ดูข้อ 2.5)

viewer   : select ทุกตาราง business (ไม่เห็น audit_logs)
analyst  : viewer + insert/update categories, datasets, import
admin    : ทั้งหมด + soft delete + เห็น audit_logs
```

## 7. Overview KPI → source field / deterministic formula

ทุกตัวคำนวณด้วย SQL ไม่ใช่ AI (Master Spec §7)

| KPI | source | formula | ข้อควรระวัง |
|---|---|---|---|
| **Ads ทั้งหมด** | `dataset_ads` | `count(distinct ad_ref) where dataset_id = ?` | นับ master ad ไม่ใช่แถวใน JSON |
| **Pages ที่พบ** | `ads.page_ref` | `count(distinct page_ref)` ใน scope dataset | เป็น Page ไม่ใช่ Brand (CLAUDE.md ข้อ 9) |
| **Ads ใหม่ 30 วัน** | `ads.first_seen_at` | `count(*) where first_seen_at >= now() - 30d` | ⛔ **ต้องนิยาม first_seen ก่อน** (ข้อ 2.1) ถ้าใช้ `start_date` แทนจะได้คนละความหมาย |
| **Evergreen / รันนาน** | `ads.start_date`, `ads.is_active` | `count(*) where is_active and (current_date - start_date) >= :threshold` | ⛔ **ต้องกำหนด default threshold** (§11 บอก e.g. 90) และเก็บใน settings |
| **Creative Reuse** | `ads.collation_count` | `count(*) where collation_count > 1` และ `/ count(*) where collation_count is not null` | coverage 93% → **ต้องแสดง denominator** ไม่ใช่ % ของทั้ง dataset |
| Ads Started Timeline | `ads.start_date` | `count(*) group by date_trunc('week', start_date)` | 100% coverage ปลอดภัย |
| Format distribution | `ad_observations.display_format` (ล่าสุด) | `count group by display_format` | 100% coverage |
| CTA distribution | `ad_observations.cta_type` | `count group by cta_type where cta_type is not null` | **coverage 86% → ต้องเขียน "จาก 294/342 ที่อ่านได้"** |
| Platform coverage | `ads.publisher_platform[]` | `unnest` แล้ว count ต่อค่า | **multi-value — ห้าม pie chart, รวมกันเกิน 100% ได้** (CLAUDE.md ข้อ 8) |
| Top Pages | `ads.page_ref` | `count(*) group by page_ref order by desc` | เรียก "observed ad activity" ไม่ใช่ market share (§4) |
| Page likes | `page_observations.page_like_count` | **median / max ต่อเพจ** | ⛔ **ห้าม sum** (§10) |
| Data Quality strip | `dataset_quality` | `present_count / total_count` ต่อ field | `impressions_with_index` ต้องนับเป็น null-object |

**KPI ที่ยังคำนวณไม่ได้จนกว่าจะปิด gap ข้อ 2:** `Ads ใหม่ 30 วัน` และ `Evergreen` — ทั้งคู่ติดนิยาม/threshold ที่ยังไม่มีในเอกสาร

## 8. สิ่งที่ทำไม่ได้จาก source ปัจจุบัน

### ทำไม่ได้ถาวรจนกว่าจะมี provider ใหม่

performance ทุกชนิด (engagement, reach, impressions, spend, CTR, CPC, CPA, ROAS, sales, conversion) — **ยืนยันด้วยการวัด: 0/342**

### ทำไม่ได้เพราะ source ว่าง

| อยากทำ | ทำไมไม่ได้ |
|---|---|
| รายงานแยกจังหวัด/ประเทศ | `targeted_or_reached_countries` = 0/342 |
| ตัวเลข impression | `impressions_with_index` = null-object 342/342 |
| งบโฆษณา | `spend`/`currency` = 0/342 |
| ad age จาก active time | `total_active_time` = 1/342 |

### ทำได้แต่ต้องมี warning เสมอ (< 50%)

`title` 45% · `link_url` 18% · `caption` 17% · `link_description` 6% · `cards` 5%
→ ทุก insight ที่ใช้ฟิลด์นี้ต้อง scope เป็น readable subset

### ทำไม่ได้เพราะยังไม่มี mapping

- **Brand-level analysis** — ต้องมี `brands` + human review (Phase 2+)
- **Creative reuse ข้าม ad** — มีแค่ `collation_count` ยังไม่มี fingerprint (ข้อ 2.3)

### ทำไม่ได้เพราะยังไม่มีข้อมูลหลายรอบ

- **แนวโน้ม / historical** — มี run เดียว (16 ส.ค.) ต้องมีอย่างน้อย 2 run ถึงเทียบได้
- **Newly Found** — นิยามคือ "first observed in latest run" ต้องมี run ก่อนหน้าเทียบ
