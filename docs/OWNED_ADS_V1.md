# เว็บแอดคู่แข่งและแอดของเรา — รุ่นแรก

วันที่: 2026-09-28

ผู้ใช้สั่งให้เริ่มสร้างเว็บ หลังยืนยันว่าต้องมีทั้งสองส่วน การตัดสินใจด้านล่างเป็นค่าเริ่มต้นสำหรับรุ่นแรก ไม่ใช่คำตอบที่ผู้ใช้ให้กับคำถาม 16–19

## การใช้งาน

- `/competitors`: เลือกรอบข้อมูลประเทศไทย ค้นข้อความ กรอง ดูการ์ด/ตาราง และเปิดรายละเอียดพร้อมหลักฐาน โดยใช้ Explorer และประวัติเดิม
- `/owned-ads`: นำเข้า CSV ของบริษัท ตรวจตัวอย่างในเครื่องก่อนบันทึกให้ทีม เลือกรายงาน ค้นและกรองแอด ดู KPI และรายละเอียดแอดจากรายงานที่เลือก
- หน้าหลักและเมนูมีทางเข้าทั้งสองส่วน ผู้ใช้ viewer ไม่ได้รับข้อมูลผลงานบริษัท; analyst และ admin ใช้งานส่วนนี้ได้

## ข้อมูลและสูตร

รายงานบริษัทเป็น snapshot ของบัญชี สกุลเงิน และช่วงวันที่หนึ่งช่วง เก็บแต่ละรายงานแยกกัน ไม่มีการบวกรวมรายงานช่วงเวลาทับซ้อน ตัวตน `ad_id` ในรายงานบริษัทแยกจาก `ad_archive_id` ของคู่แข่ง

ค่าที่ไฟล์ไม่ส่งมาคือไม่ทราบ แสดง `—` ไม่แทนด้วยศูนย์ ยอดซื้อที่รายงานให้เครดิตไม่ใช่ยอดรับเงินจริงจากออเดอร์หรือบัญชีบริษัท

- ค่าโฆษณา: รวม `spend` ของแอดในขอบเขตที่แสดง
- มูลค่าซื้อที่รายงาน: รวม `purchase_value` ตามแหล่งรายงาน
- การสนทนา: รวม `conversations` ตามนิยามในรายงาน ไม่ยืนยันว่าเป็นลูกค้าไม่ซ้ำ
- ROAS: มูลค่าซื้อรวม / ค่าโฆษณารวม เมื่อมีข้อมูลครบในขอบเขตเดียวกันและตัวหารมากกว่าศูนย์ ไม่เฉลี่ย ROAS รายแอด
- ข้อมูลบางส่วนต้องแสดงจำนวนแอดที่มีฟิลด์นั้น การคำนวณอัตราส่วนต้องไม่จับตัวเศษและตัวหารจากคนละกลุ่ม

## ขอบเขตรุ่นแรก

นำเข้าไฟล์จริงก่อน โดยเตรียมให้เชื่อม Meta อัตโนมัติเป็นงานต่อจากการตั้งค่าบัญชีและสิทธิ์ ไม่สร้าง token ตัวอย่าง ไม่ใช้ข้อมูลจำลองเป็นผลจริง และไม่ส่งคำสั่งเปิด–ปิดแอดหรือปรับงบ

ยังต้องเชื่อมแหล่งออเดอร์/แชทของทีมก่อนแสดงยอดปิดการขายจริงหรือเปอร์เซ็นต์ปิดการขาย ส่วน AI/OCR/ถอดเสียงและการติดตามอัตโนมัติยังเป็นขอบเขตที่ตกลงไว้สำหรับงานต่อ ไม่แสดงว่าเปิดใช้งานแล้ว

## การตรวจรับ

1. ผู้ใช้ที่มีสิทธิ์นำเข้า CSV ถูกต้องและเปิดอ่านรายงานเดิมได้หลังโหลดใหม่
2. CSV ที่เสียหาย ตัวเลขผิด ช่วงวันที่ผิด หรือแอดซ้ำ ต้องไม่ถูกบันทึกครึ่งหนึ่ง
3. ค้นหา/กรอง/เปลี่ยนการ์ด–ตาราง/เปิดรายละเอียดได้ และระบุบัญชี ช่วงเวลา แหล่งข้อมูล
4. ผู้ไม่ได้ล็อกอินและ viewer อ่านหรือเขียนรายงานบริษัทผ่าน API/ฐานข้อมูลไม่ได้
5. ฟิลด์ที่ขาดและตัวหารศูนย์ไม่กลายเป็น KPI ที่หลอกว่าเป็นศูนย์จริง
6. หน้าใหม่ใช้งานได้บนมือถือและด้วยคีย์บอร์ด

## การตั้งค่าใช้งาน

ใช้ Supabase และระบบล็อกอินเดิม ต้องใช้ migration ตารางรายงานบริษัทก่อนบันทึก CSV ดูไฟล์ migration ที่เพิ่มใน `supabase/migrations` และตรวจเป้าหมายฐานข้อมูลก่อนรัน ห้ามใช้ชุดทดสอบที่ล้างตารางกับข้อมูลจริง

ไม่มีการเรียกเก็บเงินจากผู้ให้บริการเก็บข้อมูลหรือ AI ในการนำเข้า CSV รุ่นนี้ ค่าโฮสต์/ฐานข้อมูลยังขึ้นกับระบบที่ใช้อยู่

- ชุดตรวจ parser/สูตร/สิทธิ์หน้า/โครง migration/รูปแบบ UI ผ่าน 72 ข้อ

- รัน browser check ซ้ำได้ด้วย `npm run build` แล้ว `node e2e/owned-dashboard.mjs` ใช้พอร์ต 3188 และ 54321; ไม่โหลด credentials ของระบบจริงเข้า service จำลอง
- ภาพทดสอบอยู่ใน `test-artifacts/owned-ads/desktop.png` และ `mobile.png` ตัวเลขในภาพเป็น fixture ที่ติดป้ายข้อมูลทดสอบ
- `tests/db/owned-ads.test.ts` ยังไม่ได้รันกับฐานข้อมูลจริง เพราะ local PostgreSQL/Supabase ไม่เปิดใช้งาน และ `.env.local` ชี้ไปที่ระบบใช้งานจริง

ก่อนเปิดบันทึกรายงานให้ทีม ต้องทดสอบและติดตั้ง `0042_owned_ad_reports.sql` ผ่านกระบวนการ migration ของโครงการ ไฟล์ rollback จะลบรายงานบริษัททั้งหมด จึงต้องสำรองก่อนใช้ ยังไม่มีการติดตั้ง migration บนระบบจริงในงานนี้

การเชื่อมบัญชี Meta อัตโนมัติ, ข้อมูลออเดอร์จริง, AI/OCR/ถอดเสียง และการเก็บสื่อครบตามแผนเดิมยังไม่ได้เสร็จในรุ่นนี้
